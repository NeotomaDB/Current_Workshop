## Introduction

[Neotoma](https://www.neotomadb.org) holds diatom counts from sediment cores and surface samples. Other databases hold other information about the same diatoms: how they are classified, which names are accepted today, where else they have been recorded. This short document is a **proof of concept**. It shows that you can take the taxa from a Neotoma download, look them up in another database that has a free API, and **merge** the two. The point is to learn the skill, so we keep it small. It is not a full comparison, and it does not need to be perfect.

We connect to [**GBIF**](https://www.gbif.org), the Global Biodiversity Information Facility, because it is free, needs no key, and has an R package, `rgbif`, on CRAN. Other authorities exist: [DiatomBase](https://www.diatombase.org) is a taxonomic register for diatoms (part of WoRMS) whose names can be queried through a free service, and [AlgaeBase](https://www.algaebase.org) needs a key that has to be requested from the AlgaeBase team. The same pattern works for any of them.

To be gentle with the GBIF service we make **one** request, for a small set of names, and we saved the answer in `data/`. The names were matched on **November 03, 2026**.

## 1. Three sites from a Neotoma download

We start from a download we made on the Simple Workflow.

A `sites` object can be sliced like a list. To keep things small we take only the **first three sites** (`aggregate_dl[1:3]`). If you want other sites, change the numbers: `aggregate_dl[c(37, 38, 39)]` would give three from the middle.


``` r
aggregate_dl <- readRDS("data/aggregate_slice_download.RDS")

three_sites <- aggregate_dl[1:3]
three_samples <- samples(three_sites)
```

## 2. The unique taxa

Now we take only the diatoms (`ecologicalgroup == "DIAT"`, the water chemistry rows are not taxa), and we use the translation table from the Simple Workflow (`data/diatom_taxontable.csv`) to clean the names, for example by dropping varieties. We keep each name once, and add how many valves, samples and sites it has in Neotoma. Clean names help a lot when we look for them somewhere else.


``` r
translation <- readr::read_csv("data/diatom_taxontable.csv", show_col_types = FALSE)

neotoma_taxa <- three_samples %>%
  dplyr::filter(ecologicalgroup == "DIAT") %>%
  inner_join(
    dplyr::select(translation, variablename, harmonizedname),
    by = "variablename"
  ) %>%
  group_by(harmonizedname) %>%
  summarise(
    valves = sum(value),
    samples = n_distinct(sampleid),
    sites = n_distinct(siteid),
    .groups = "drop"
  ) %>%
  arrange(desc(valves))
```

## 3. Finding the taxa in GBIF {.tabset}

`rgbif` has a function that takes a whole table of names and matches them against the GBIF taxonomy in one go: `name_backbone_checklist()`. We give it our names, and we also give it the **class**, *Bacillariophyceae* (the diatoms). This matters, because the same name can mean different organisms: a genus name can be reused for an animal or a plant. With the class, GBIF knows we mean the diatom.

### Code


``` r
library(rgbif)

# One request for all the names. We name the column `scientificName`, which is
# what rgbif looks for.
gbif_match <- name_backbone_checklist(
  data.frame(
    scientificName = neotoma_taxa$harmonizedname,
    class = "Bacillariophyceae"
  )
)

# Save the answer so we do not need to ask GBIF again.
saveRDS(
  list(retrieved = Sys.time(), match = gbif_match),
  "data/gbif_match_three_sites.RDS"
)
```

For each name GBIF tells us the taxon it matched (`canonicalName`), at what `rank`, whether that name is `ACCEPTED` or a `SYNONYM`, how it matched (`matchType`: `EXACT`, `FUZZY` when the spelling was slightly different, or `HIGHERRANK` when it could only find a higher group), a `confidence` score, and the classification (`family`, `order`).

## 4. Merging the two

Both tables have the name (`harmonizedname` in Neotoma, `verbatim_name` in GBIF's answer, which is the name we sent). We join them with `left_join()`, which keeps every Neotoma taxon, with or without a match, and adds the GBIF columns. For taxa that GBIF treats as synonyms we also bring in the accepted name.


``` r
gbif_small <- gbif_match %>%
  dplyr::select(
    harmonizedname = verbatim_name,
    gbif_name = canonicalName, rank, status,
    match_type = matchType, confidence,
    accepted_name = acceptedScientificName, family, order
  )

merged <- neotoma_taxa %>%
  left_join(gbif_small, by = "harmonizedname")
```

## Summary

-   **It is possible to merge Neotoma with other authorities.** In a few lines of code we took the unique taxa from three Neotoma sites, looked them up in GBIF with a single request, and joined the answer back.
-   **Match names with care.** Use the class so that a genus is not confused with an animal of the same name, check the `matchType` and the `status`, and expect some synonyms and some matches at a higher rank. It does not need to be perfect to be useful.
-   **Be gentle with the service.** Ask for many names in one request, keep the answer (`saveRDS()`), and do not loop over thousands of taxa.
-   **The same pattern works elsewhere.** Clean your names, send them to another source, and `left_join()` the answer. If you want occurrence records (not just names), `rgbif` can also search and count GBIF records, and `occ_download()` gives a citable set of records with a DOI.
